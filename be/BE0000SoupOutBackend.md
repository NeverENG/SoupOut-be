# M02 架构

```
   Godot 客户端 ──UDP──▶ soup-engine (Rust) ──UDS──▶ Go 逻辑服 + soup-sdk-go
                          通用 · 可复用            本游戏专有

   单进程 · 零后端 · 零数据库 · 零 cgo
```

| 决定 | 理由 |
|---|---|
| **Rust 管字节，Go 管状态** | 边界是「解码后的消息进出」 |
| **tick 在 Go，Rust 从不阻塞等 Go** | 避免 Rust→Go 的 cgo 回调（最贵的方向），也让两侧能独立部署重启 |
| **双进程 / UDS，不用 cgo** | Go 保持纯 Go；副产物是**逻辑服可以 `kill -9` 热重启，玩家不掉线** |
| **单进程、零持久化** | 一局约 3 分钟，进程挂了对局丢失是可接受代价 |
| 房间码 + 匹配队列在内存 | 没有 Meta 后端，没有数据库 |

# M05 服务端最容易做错的十件事【硬约束速查】

> 每一条都不是打磨，是正确性。做反了要返工。

### ① 【最高优先级】不得假设游戏状态是「实体列表」
框架和 SDK 的内核里**禁止**出现 `[]Entity` / `RegisterEntity` / `NetworkedField`。
本作的同步对象是一片被 4 人同时改写的**连续区域场**，焊了实体表就跑不起来。
框架只知道「某客户端某 tick 要一段字节，可相对某 baseline 做增量」。（`T0003M01F02`）

### ② `EncodeSnapshot` 不返回值，只往给定 buffer 里写
返回 `[]byte` = 每客户端每 tick 一次分配 = 每秒数万次 + GC 压力。（`T0003M02F02`）

### ③ Go 侧发送用 `BeginSend`/`Commit`，不用 `func(*Buffer)` 闭包
**Go 闭包一旦捕获外部变量就逃逸到堆**，热路径上是隐形分配源。（`T0003M02F03`）

### ④ 地盘增量是「自上次 ACK 累积」，不是「逐帧」
地盘场不像玩家位置那样每帧自愈——丢一个逐帧增量包，客户端会一直显示错的归属，直到 5 秒后的关键帧。
累积式增量丢包后下一个包仍带着那些格子，自愈。（`T0001M03F06`）

### ⑤ `DiffSince` 不许用全格扫描
9216 格 × 4 客户端 × 10Hz × 数百房间 = 内存带宽灾难。
用**环形变更日志 + 复用 bitset 去重**，开销只跟实际变更数（个位数）成正比。（`T0004M03F01`）

### ⑥ `Tick` 的执行顺序是契约
复活 → 移动 → 交互 → 扩张 → 流失 → 战斗 → 道具 → 质量重算 → 结算 → 事件。
**扩张必须在移动之后**（膨胀源是当前位置）；**战斗用的是上一 tick 算出的质量属性**（避免同 tick 因果环）。（`T0004M04`）

### ⑦ 房间内：不遍历 map、不起 goroutine、不用 `time.Now`/`math/rand`
确定性回放的前提。**Go 的并发红利在房间之间，不在房间内部**——一个房间一个 goroutine，就地算完。（`T0003M06`）

### ⑧ 全线定点，`sim` 与 `territory` 内不出现浮点
Chamfer 距离用整数（正交 +8，对角 +11），其余走 `pkg/fixed`（Q22.10）。
堆元素打包成 `uint32 = dist<<16 | cell`，**平局顺序确定**。（`T0004M03F01` · `M05`）

### ⑨ 实时消息不进 WorkerPool
Zinx 把所有消息塞 worker pool，动作游戏这么做会引入不可控的调度抖动。
输入包直接投递到房间 mpsc；WorkerPool 只处理握手、鉴权、查询这类可以慢几毫秒的。（`T0002M02F02`）

### ⑩ 零分配断言进 CI
`Tick` + `EncodeSnapshot` 稳态 **0 次分配**，用 `testing.AllocsPerRun` 断言。
Rust 侧同理：稳态 0 次/包，用 `dhat` 或计数 allocator 验证。**后期再回来抠会很痛。**

# M06 开发顺序

## BE0000M06F01 Rust 线（`T0002M09`）

| 里程碑 | 内容 | 出口 |
|---|---|---|
| **E1** | UDP 收发、包格式、握手、会话表、UDS 帧流 | Go 侧能 echo 一条消息回客户端 |
| E2 | seq/ack、四通道、重传、分片、心跳 | 模拟 150ms+5% 丢包，Ch2 不丢不乱 |
| E3 | 重连宽限期、NAT 漂移、背压、逻辑服热重启 | `T0002M08F02` 集成场景全过 |
| E4 | fuzz、HMAC、限流、metrics、`engineload` | 性能指标回填实测 |

**E1–E4 全程不依赖任何游戏内容，现在就能开工。**

## BE0000M06F02 Go 线（`T0004M07`）

| 周 | 内容 | 出口 |
|---|---|---|
| **W1** | `pkg/fixed` + **`internal/territory`** | `T1–T8` 全过，可视化能看到膨胀 |
| W1–2 | `cmd/mockengine` + SDK S1/S2 | **Pong 跑通** |
| W2–3 | `proto` + `sim` + `room` + `lobby` | 4 个 `botclient` 打完整局并正常结算 |
| W3–4 | SDK S3（抖动 / baseline / 关键帧 / 重连） | 150ms+5% 丢包下正常；断连 10s 重连一致 |
| W4+ | 切真 Rust 框架联调 | —— |

> **两条最重要的：**
> - **先写 `cmd/mockengine`（约 200 行）**，Go 侧就不用等 Rust。等 E1 好了换一行 socket 地址即可
> - **`territory` 第一个做，而且脱离网络单独做透。** 它是全项目风险最高的算法，且不依赖任何其他东西
